# 老人购物｜前端技术适配说明

> 文档版本：V1.0  
> 编写日期：2026-08-31  
> 适用阶段：第七阶段——前端视觉设计适配与代表页改版  
> 状态：开发前确认稿

## 1. 项目判断

- 产品类型：面向老年人的日常用品购物 Web 原型，并提供家人协助和 AI 语音/文字助手。
- 主要用户：需要简单购物流程的老人；协助代买、代付和售后的家人。
- 主要终端：移动 Web 优先，同时兼顾平板和桌面浏览器。
- 项目状态：已有可运行的前端功能原型和 FastAPI 后端，不进行框架迁移或业务重写。
- 当前阶段目标：在不破坏第一至第六阶段业务闭环的前提下，建立统一视觉语言，完成首页代表页设计与验证，再逐步覆盖核心页面。

## 2. 已读取资料与现状

- 已读取：产品 PRD《老人购物》。

- 当前已有：商品浏览/搜索、购物车、订单、售后、家人协助、语音/文字助手和 FAQ 来源展示。

## 3. 技术选择

### 3.1 实际技术栈

| 能力 | 当前采用 | 适配结论 |
|---|---|---|
| 应用框架 | Next.js 15.5.24 App Router | 保留，已有路由结构稳定 |
| UI 框架 | React 19.0.0 | 保留 |
| 语言 | TypeScript 5.8.2，strict | 保留，禁止用 `any` 绕过核心类型 |
| 样式 | Tailwind CSS 3.4.17 + `globals.css` | 保留，不在本阶段升级 Tailwind 大版本 |
| 组件库 | 原生 HTML/React 业务组件 | 继续优先复用；复杂无障碍组件再单独引入 |
| 图标 | 当前以文字/少量符号为主 | 设计阶段统一图标策略，正式功能不使用表情符号代替图标 |
| 数据请求 | `frontend/lib/api.ts` 集中封装 | 保留，页面不直接散落 `fetch` |
| 客户端状态 | 页面局部 React state | 当前复杂度足够，不引入 Zustand/TanStack Query |
| 测试与交付 | TypeScript、ESLint、Next build，后端真实接口验收 | 保留并增加页面人工验收；暂不虚构未配置的前端测试脚本 |

### 3.2 不采用的默认方案

- 不因为手册参考基线而升级到 Next.js 16 或 Tailwind CSS 4，避免视觉阶段引入无关风险。
- 暂不引入完整 UI 组件库、全局状态库、表单库、图表库或动画库。
- 暂不引入 TanStack Query：当前页面请求数量和共享缓存复杂度尚未达到引入条件。
- 暂不引入 PWA、离线购物、推送和微信小程序能力。

## 4. 视觉适配方向

### 4.1 核心设计原则

1. **看得清**：正文保持大字号，重要信息有明确层级，避免低对比度灰字。
2. **点得准**：主要按钮和触控目标不小于 48×48px，操作间距足够。
3. **步骤少**：首页优先呈现搜索/说话、分类、商品和购物车入口，不让装饰抢占任务路径。
4. **状态明白**：加载、空数据、失败、等待确认、成功和权限受限分别表达。
5. **家人可接手**：家人协助页面与老人端共用颜色、状态和按钮语义，但突出家人任务。

### 4.2 建议视觉语言

- 基调：温暖、可信、清楚，不采用过度科技化的 AI 深色工作台风格。
- 背景：暖米白作为页面背景，白色作为内容卡片。
- 主色：深绿色，用于主要行动和可信赖感。
- 强调色：深蓝，用于标题和主要文本；橙色只用于提醒或等待确认。
- 风险色：红色只表示错误、退款/售后风险和不可继续状态。
- 圆角：采用参考页的 4px 低圆角，弹窗最多 8px；通过边框、留白和轻阴影建立层次，同时保证老人端控件容易辨识。
- 阴影：只保留轻微层次，避免影响文字边缘和对比度。
- 字体：中文优先使用系统字体回退链，不加载未经确认的商业字体。

### 4.3 设计变量要求

下一阶段应把颜色、字号、间距、圆角、阴影、控件高度集中为语义变量，例如：

```css
:root {
  --color-bg: #f7f7f4;
  --color-surface: #f2f1ed;
  --color-text: #26251e;
  --color-muted: #66655f;
  --color-primary: #34785c;
  --color-accent: #f54e00;
  --color-warning: #c08532;
  --color-danger: #b42318;
  --radius-control: 4px;
  --control-min-height: 52px;
}
```

具体色值在代表页评审后冻结；未确认前，不在每个页面继续扩散新的颜色值。

## 5. 前端架构适配

当前依赖方向保持为：

```text
路由页面
  ↓
业务组件与局部 Hook
  ↓
frontend/lib/api.ts
  ↓
FastAPI /api/v1
```

- 路由页面继续位于 `frontend/app/`。
- 业务组件继续位于 `frontend/components/`，优先小范围提取，不做大规模目录迁移。
- 接口类型和请求继续集中在 `frontend/lib/api.ts`。
- 视觉 Token 放入 `frontend/app/globals.css` 或后续独立样式目录；不把配色散落到页面。
- 当前页面大多使用 Client Component，因为商品筛选、购物车、订单操作和语音助手依赖浏览器事件与局部状态。
- 当前没有长任务流式页面；AI 助手是短请求 + 有限历史，因此暂不引入 SSE、WebSocket 或轮询。

## 6. 状态与安全适配

### 6.1 状态分层

| 状态 | 当前事实来源 | 前端处理 |
|---|---|---|
| 商品、购物车、订单、售后 | 后端 API | 请求后渲染，刷新后重新获取 |
| 商品详情/订单详情 ID | URL 路由参数 | 使用路由恢复，不依赖内存 |
| 搜索词、分类、弹窗、提交中 | 页面 React state | 仅保存当前页面临时状态 |
| AI 最近对话 8 条 | 当前助手组件内存 | 会话期间使用，刷新后不承诺长期恢复 |
| 用户偏好 | 当前未实现 | 不在本阶段擅自加入 Local Storage |

### 6.2 Agent 交互

- 当前助手状态为输入、语音监听、处理中、成功回复和错误。
- 后端 Tool Calls 仅允许商品、订单、FAQ 只读查询；前端不展示原始工具参数或内部提示词。
- `needs_confirmation` 只展示明确的页面确认提示；付款、退款、改地址和确认收货仍由业务页面与后端状态机控制。
- `provider`、`model` 和 FAQ 来源可作为低优先级详情展示，不应成为老人理解任务的前提。

### 6.3 安全边界

- API Key 只在后端 `.env`，不进入 `NEXT_PUBLIC_` 变量、客户端 Bundle 或浏览器存储。
- 前端隐藏按钮不等于权限控制，家人权限仍以服务端校验为准。
- 前端不信任金额、订单状态或商品结果；展示前沿用后端返回和现有适配类型。
- 错误界面只显示可理解的用户文案，不暴露堆栈、密钥或完整内部请求内容。

## 7. 响应式与无障碍目标

- 验收宽度：390px、768px、1280px、1440px。
- 390px 是首要目标：老人能够完成搜索、查看商品、加入购物车和打开订单。
- 页面不得产生无意横向滚动；卡片网格在小屏幕改为单列或可读的两列布局。
- 顶部导航在手机上应有清晰的折叠或重排方案；不能用过小文字挤在一行。
- 触控目标建议不小于 48×48px；键盘 focus 必须明显。
- 表单控件拥有可关联 Label；状态不能只靠颜色；错误信息使用 `role="alert"` 或等价可访问方式。
- 语音能力必须保留文字输入回退；未授权、浏览器不支持和识别失败都要有明确文案。

## 8. 与前端通用手册的偏离

| 偏离项 | 原因 | 影响与控制 |
|---|---|---|
| 未采用手册参考的 Next.js 16/Tailwind 4 | 当前项目已稳定运行在 Next.js 15/Tailwind 3 | 锁定现有版本，避免设计阶段出现框架迁移风险 |
| 未引入 TanStack Query/Zustand | 当前为单演示用户、低并发原型，状态规模较小 | 继续集中请求层；复杂度增加后再评估 |
| 尚未配置 Vitest/RTL/Playwright | 当前前端工程只有 lint、typecheck、build，后端已有回归测试 | 本阶段先补浏览器人工验收；后续正式视觉定稿后增加关键 E2E |
| AI 助手不采用流式输出 | 当前后端接口为短请求，Tool Calls 为有限两段请求 | 继续使用处理中状态，未来出现长任务再引入流式协议 |

## 9. 本阶段待确认事项

以下事项会影响视觉方向，需在代表页评审时确认：

- 品牌名称、Logo 和是否使用正式品牌色。
- 是否提供设计稿、参考网站或字体规范。
- 老人端是否需要固定底部导航，还是保留顶部导航。
- 首页首屏优先突出“搜索商品”还是“语音助手”。
- 家人协助页是否采用与老人端一致的极简布局，还是允许更高的信息密度。

如果暂时没有以上资料，默认按本声明的暖色、大字号、移动优先方向推进，不阻塞代表页实现。
