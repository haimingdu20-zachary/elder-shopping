> 当前状态：开发中：首页代表页第一版已完成

## 1. 本阶段目标

把当前已完成业务功能的前端原型，推进为一套老人能看清、点准、走完流程的统一视觉界面；先完成首页代表页和设计基础，再根据代表页确认结果覆盖核心页面。

本次视觉参考：[Refero｜Cursor Style](https://styles.refero.design/style/4e3b4717-84c8-4599-baaf-a343c3d619b6)。实际落地采用其暖米白、暖黑、骨色纸张表面、4px 低圆角和细边框语言，并将字号、触控尺寸和交互密度调整为老人端标准。

本阶段不改变后端业务规则，不重写第一至第六阶段接口，不把视觉原型误认为正式生产产品。

## 2. 范围

### 2.1 本阶段包含

- 建立前端颜色、字号、间距、圆角、阴影和控件尺寸 Token。
- 统一页面外壳、顶部导航、页面容器、卡片、按钮、输入框、状态提示和确认区域。
- 完成首页代表页：欢迎区域、AI 助手、搜索、分类、商品卡片、购物车入口和联系客服入口。
- 对首页在 390px、768px、1280px、1440px 做响应式检查。
- 保持首页真实调用 `/categories`、`/products` 和 `/assistant/chat`。
- 统一 AI 助手的处理中、错误、FAQ 来源、确认提示和语音不可用状态。
- 输出代表页人工验收清单，产品确认后再铺开订单、购物车和家人协助页面。

### 2.2 本阶段不包含

- 不更换 Next.js、React、Tailwind 或目录架构。
- 不接入真实支付、真实物流、真实登录、短信通知或微信小程序。
- 不让 AI 直接执行付款、退款、改地址、确认收货等高风险操作。
- 不新增长任务流式协议、PWA、离线购物或复杂全局状态库。
- 不在没有设计稿确认前一次性大规模改完所有页面。
- 不把 API Key 放到前端，不把后端商品/订单数据复制成前端固定 Mock。

## 3. 目标用户流程

### 3.1 老人购物主流程

```text
打开首页
→ 看懂“搜索/说话”入口
→ 输入或说出“帮我找牛奶”
→ 看到商品结果
→ 打开商品详情
→ 加入购物车
→ 确认地址和金额
→ 进入模拟支付
→ 在订单中查看状态
```

### 3.2 AI 助手分支

```text
输入/语音
→ 处理中
→ 返回商品、订单或 FAQ 结果
→ 若是高风险意图，显示需要用户确认
→ 跳转到对应业务页面
```

### 3.3 家人协助分支

```text
老人订单
→ 请求家人付款/售后协助
→ 家人协助页查看请求
→ 家人查看订单详情
→ 完成模拟付款或协助处理
```

## 4. 页面和组件计划

### 4.1 当前页面路由

| 路由 | 页面用途 | 本阶段策略 |
|---|---|---|
| `/` | 老人首页、商品搜索、AI 助手 | 首个代表页，优先改版 |
| `/products/[id]` | 商品详情 | 沿用接口和流程，统一组件后改版 |
| `/cart` | 购物车 | 统一金额、数量和主按钮层级 |
| `/checkout` | 确认订单 | 强化地址、金额、确认前提示 |
| `/orders` | 订单列表 | 统一状态标签和空/失败态 |
| `/orders/[id]` | 订单详情 | 突出下一步业务动作 |
| `/after-sales/[orderId]` | 售后申请 | 突出风险说明和二次确认 |
| `/family` | 家人协助首页 | 统一但允许更高信息密度 |
| `/family/orders/[id]` | 家人查看订单 | 复用订单详情展示规则 |
| `/family/requests/[id]` | 家人请求详情 | 突出请求类型、权限和动作 |
| `/support` | 客服提示页 | 保留真实能力边界，不伪造客服处理 |

### 4.2 组件分层

优先复用现有组件：`LargeButton`、`ProductCard`、`OrderStatus`、`AssistantPanel`、`SupportEntry`、订单/家人详情组件。

设计阶段补齐或统一以下基础能力：

- `PageContainer`：页面最大宽度、水平内边距和响应式节奏。
- `Button` 状态：默认、悬停、聚焦、禁用、提交中、危险操作。
- `Input` 状态：默认、聚焦、错误、禁用。
- `StatusNotice`：加载、空、失败、成功和需要确认。
- `SectionHeading`：标题、说明和辅助动作的统一排布。
- `ProductCard`：图片占位、价格、配送说明和可操作入口。
- `AssistantPanel`：文字输入、语音状态、处理中、回复、来源和跳转。

不为了复用而制造带大量条件参数的万能组件；重复模式稳定后再抽象。

## 5. 首页页面状态矩阵

| 模块 | 初始 | 加载 | 空 | 等待确认 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|
| 分类 | 未请求 | 显示加载提示 | 无分类时保留商品浏览 | 不适用 | 显示分类按钮 | 显示分类加载失败 | 刷新后重新请求 |
| 商品列表 | 未请求 | 显示“正在准备商品” | 显示换词建议 | 不适用 | 显示真实商品卡片 | 显示可理解错误 | 重新加载当前筛选 |
| 搜索框 | 空输入 | 提交时按钮禁用 | 空输入不提交 | 不适用 | 保留搜索词和结果 | 保留输入并提示原因 | 页面返回后保留当前页临时状态 |
| AI 助手 | 等待输入 | 显示“处理中”且禁止重复提交 | 不展示空回复卡片 | 高风险结果提示按页面继续 | 显示回复和下一步建议 | 显示错误及文字输入回退 | 会话内保留最近 8 条消息 |
| 语音入口 | 未检测 | 正在监听 | 浏览器不支持时显示文字入口 | 不适用 | 转写后填入输入框 | 授权/识别失败提示 | 可重新发起监听 |
| 购物车入口 | 可点击 | 不单独请求 | 无商品时仍可打开空购物车 | 不适用 | 跳转购物车 | 跳转失败显示提示 | 重新打开页面 |

## 6. 核心页面状态要求

### 6.1 商品详情

- 加载时不能先显示不存在的商品。
- 商品图片失败时显示稳定占位，不影响标题、价格和加入购物车。
- 数量修改有边界提示，加入购物车后给出明确反馈。
- 库存、配送、退货说明使用后端字段，不由前端猜测。

### 6.2 购物车与确认订单

- 空购物车和接口失败分开显示。
- 数量操作提交期间防止重复点击。
- 金额以服务端返回为准；确认前突出地址、商品、数量、配送和总金额。
- 创建订单使用现有幂等键；超时后不能直接重复创建。

### 6.3 订单与售后

- 订单状态标签必须配合文字，不能只用颜色。
- 订单详情优先展示当前可执行的下一步。
- 售后页面展示退款/退货影响、金额去向和模拟状态说明。
- 最终提交继续使用二次确认和后端状态机。

### 6.4 家人协助

- 明确当前是老人订单还是家人代买订单。
- 显示请求类型、请求状态、涉及订单和家人权限。
- 家人可完成的动作与老人不可完成的动作不能混淆。
- 模拟付款成功、取消和重复操作均应显示可理解反馈。

## 7. 接口契约与前端调用

### 7.1 本阶段使用接口

| 功能 | 方法与路径 | 前端用途 |
|---|---|---|
| 分类 | `GET /api/v1/categories` | 首页分类筛选 |
| 商品 | `GET /api/v1/products?q=&category_id=` | 商品列表和搜索 |
| 助手 | `POST /api/v1/assistant/chat` | 文字/语音转写后的意图处理 |
| 知识 | `GET /api/v1/knowledge/search?q=` | 仅作为独立接口验收，不在页面另造数据 |
| 健康 | `GET /api/v1/health` | 本机服务状态检查 |

后续页面继续使用当前 `frontend/lib/api.ts` 中的订单、购物车、售后和家人协助函数，不在组件内直接拼接 API 地址。

### 7.2 助手请求与响应

请求使用：

```json
{
  "text": "帮我找牛奶",
  "user_id": "demo-elder",
  "conversation_id": "当前会话 ID",
  "history": [{"role": "user", "content": "我想买日用品"}]
}
```

前端只使用以下可见结果：

- `reply`：老人能理解的回复；
- `action`：决定跳转商品搜索、订单或 FAQ 来源；
- `needs_confirmation`：是否提示用户到页面确认；
- `suggestions`：最多展示三条下一步建议；
- `provider/model`：低优先级技术详情；
- `warning`：仅转为用户可理解的降级文案。

`tool_calls` 是内部可追溯信息，设计稿默认不直接展示工具名；如需展示，使用“已查询商品/订单/平台说明”等产品语言。

## 8. 实现方案

### 8.1 开发顺序

1. 盘点现有页面截图和问题，不先改业务逻辑。
2. 在 `globals.css` 建立语义 Token 和基础控件状态。
3. 改造 `layout.tsx` 的页面外壳和导航响应式行为。
4. 改造首页代表页及现有基础组件。
5. 在真实后端运行状态下验证首页搜索、助手、商品卡片和购物车入口。
6. 产品确认代表页后，再按“商品详情 → 购物车 → 确认订单 → 订单 → 家人协助”的顺序铺开。

### 8.2 状态来源

- 商品/分类/订单/售后/家人请求：后端 API 是事实来源。
- 当前输入、弹窗、提交中：局部 React state。
- 产品详情 ID、订单 ID、家人请求 ID：路由参数。
- 助手会话：组件内 `conversationIdRef` 和最近 8 条消息；本阶段不新增长期记忆。

### 8.3 响应式实现

- 使用 Tailwind 现有断点和少量 CSS 变量，不新增复杂布局依赖。
- 以 390px 为设计起点，再扩展到平板和桌面。
- 商品卡片在窄屏保持可读，按钮和价格不被压缩到不可操作。
- 顶部导航在窄屏重排；若确认需要抽屉，再实现遮罩、关闭和焦点行为。

### 8.4 性能与安全

- 不新增大型组件库、图表、动画和字体资源。
- 商品图片继续使用本地/后端提供的资源；图片失败必须有占位。
- 不将商品列表、订单列表或大对象写入 Local Storage。
- 不在前端读取 `.env` 中的 DeepSeek Key。
- 生产构建后继续检查静态资源和 API 地址配置。

## 9. 验收标准

### 9.1 自动检查

在项目根目录执行：

```bash
cd frontend
npm run typecheck
npm run lint
npm run build
```

后端回归：

```bash
PYTHONPATH=backend .venv/bin/pytest -q backend/tests
```

### 9.2 首页人工验收

在浏览器打开 `http://127.0.0.1:3000/`：

1. 390px 宽度下，首页没有横向滚动，标题、搜索框、发送按钮和商品价格清楚可读。
2. 首次加载显示加载状态；接口成功后显示商品；空结果和失败结果分别可理解。
3. 输入“帮我找牛奶”，点击发送，看到处理中状态，完成后跳转或展示牛奶结果。
4. 输入“退货怎么申请”，看到 FAQ 来源说明；页面不显示原始提示词或工具参数。
5. 输入“让家人付款”或“申请售后”，只出现确认/订单入口，不直接执行高风险操作。
6. 点击语音入口：支持时可转写；不支持、拒绝授权或识别失败时仍能使用文字输入。
7. 键盘 Tab 可以到达搜索、助手、分类、商品卡片和购物车入口，焦点清晰。
8. 在 768px、1280px、1440px 下检查内容最大宽度、卡片布局和导航，不出现遮挡。

### 9.3 代表页交付判定

- [ ] 产品确认颜色、字体、圆角、间距和首页信息层级。
- [ ] 首页真实接口可用，不以固定 Mock 宣布完成。
- [ ] 加载、空、失败、处理中、成功和语音不可用状态均可观察。
- [ ] 主要按钮触控尺寸和键盘 focus 合格。
- [ ] Console 无持续错误，Network 无未解释的重复失败请求。
- [ ] 自动检查全部通过。
- [ ] 产品确认后才进入全站页面铺开。

## 10. 风险与回退

| 风险 | 影响 | 降级/回退 |
|---|---|---|
| 暂无正式设计稿 | 可能需要调整色彩和品牌元素 | 先完成中性代表页，不冻结全站视觉资产 |
| 老人用户对信息密度反馈不一致 | 首页可能需要不同布局 | 保留单列移动方案，桌面端再增加密度 |
| 语音浏览器差异 | 真机表现不一致 | 文字输入始终可用，语音作为增强能力 |
| DeepSeek 不可用或响应异常 | 助手体验降级 | 显示规则兜底，商品/订单仍由本地后端校验 |
| 视觉改造影响既有流程 | 业务验收回归 | 每改一个页面立即走原有业务闭环，不跨阶段大改 |
